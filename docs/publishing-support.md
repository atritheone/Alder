# Alder publishing and definition cards

The publication service builds every output from the same explicit collation. It resolves section order, placement order, inclusion, a placement's selected variant or its clip's accepted variant, and frozen document/text snapshots. A muted audition track remains in the written publication unless its placement is excluded. Draft clips with no included placements are reported and omitted. Repeated placements are reported and repeated. Missing references fail visibly instead of silently changing the manuscript.

## Supported document formats

Running headers and footers support automatic Heading 1–6 fields, using the first matching heading on the physical sheet or the nearest preceding heading (then the first following heading). Values track editing and Arrangement and are calculated in desktop PDF; direct backend PDF uses its own page layout. Body heading fields resolve on insertion/Update fields and export. Native Word STYLEREF update/render/resave is qualified for built-in and dedicated custom heading styles. Mixed styles at the same level or a style shared with ordinary text cannot be represented by one native STYLEREF: DOCX export asks for one dedicated style rather than writing an incorrect field. External instructions with incompatible style scope or unsupported switches retain cached wording with a conversion warning. `test-running-headings-desktop.mjs` and `running-headings-fixture.py` cover these behaviours. General rich running objects and full-book page numbering in chapter-local editing remain open.

Table properties includes per-row keep-together or allow-across-pages settings. DOCX retains native row break flags, including after Word 16.0 rendering/resaving; HTML/EPUB preserve them. Write currently divides top-aligned paragraph cells, with independent cell page ranges, repeated headers and no orphaned header. Vertically merged/nested rows and middle/bottom-aligned split rows remain unqualified, and the dialog explains that limitation. Arrangement and desktop PDF freeze measured cell positions and paint borders without print-time reflow; middle/bottom positioning in unsplit cells is retained. Direct backend PDF honours row choices through ReportLab but still uses its separate pagination.

Heading numbering supports six decimal levels, inherited styles, explicit removal and level restarts. Heading text/number/page cross-references retain native Word fields and stable targets. In-document contents collect chosen heading levels from included chapters, with optional page numbers and an entry style. Desktop insertion, field updating and PDF calculate these numbers from the complete publication, including section numbering/restarts; HTML/EPUB preserve cached page values. Native Word 16.0 updates and resaves the supported TOC/PAGEREF representation and entry typography. Multiple contents fields share Word's global TOC styles, which is reported when their Alder entry styles differ. General external Word TOC instructions and non-desktop page-reference recalculation remain unqualified.

Named paragraph and character styles resolve base → derived style → direct formatting on an isolated publication snapshot. Missing bases and inheritance cycles fail explicitly. Null/empty properties inherit; zero spacing/indentation and false flow flags remain explicit. HTML/EPUB use resolved CSS, DOCX creates paragraph/character styles, and PDF uses its supported style mapping. The source project, variants and frozen snapshots remain unchanged. Font size (6–72 pt), paragraph alignment, multiple/exact/at-least leading, before/after spacing (0–144 pt), first-line/left/right indentation (−144–144 pt), keep-with-next, keep-together, widow/orphan and page-break-before properties are retained. DOCX import resolves Word's implicit defaults and explicit On/Off overrides. The browser normalises inline baseline boxes for exact leading; Windows checks cover Cambria, Arial and Times New Roman at mixed 36–72 pt sizes, sub/superscripts and page splits. Other font fallbacks, international scripts and platforms remain unqualified. CSS named/hexadecimal colours are normalised; translucent text colours are flattened against white with a notice. Text marks include strong/emphasis, underline, strike, sub/superscript, highlight, safe links and supported inline styling.

**Page Preview** renders the verified PDF with locally bundled PDF.js, including its worker, font and decoder resources. Desktop PDF export now uses an isolated copy of the editor's pagination and captured pages. It freezes resolved content, styles and image pixels before layout, preserves the active editing session, and verifies page count/dimensions against the captured map before publishing the result. Page navigation, zoom and the source revision remain attached to that generated artifact; **Save this PDF** saves the same proof. Its separate reflowable reading mode offers reader width, type size and section navigation, without changing project typography. Reading-mode overrides are a reader approximation; the PDF mode is the definitive page proof.

The Windows desktop route is qualified for ordinary prose/lists/merged tables, mixed section geometry/parity, cropped inline/standalone images, custom tab leaders, exact leading, paragraph decoration and internal bookmarks/references. `test-publication-layout-desktop.mjs` and `check-publication-layout.py` compare page maps and extracted words, image placement resources and link destinations. Direct backend/headless PDF export retains ReportLab's separate layout, font and tab conversion restrictions. Desktop cross-platform graphics, very large export memory, complex table pagination, flowing notes and accessible PDF tagging remain unqualified. Historical ReportLab restrictions below apply to that fallback route unless explicitly stated otherwise.

The `includeGlossary` publication option appends an alphabetically ordered glossary from the project's authored dictionary entries to every output format, including EPUB/AZW3 navigation. It includes the headword, optional IPA/part of speech and definition. Empty/incomplete entries are reported. The generated section exists only in the output snapshot; dictionary data and manuscript placements are not changed. The option defaults off and is independent of definition-card export.

TXT drops formatting and images, with a conversion warning when the document contains rich content; it preserves authored trailing spaces and empty paragraphs. Markdown uses alt text for images and tab-separated text for tables, and reports conversion of alphabetic/Roman/custom bullet markers to ordinary lists. Decimal, alphabetic and Roman numbering plus disc/circle/square bullets survive DOCX/HTML import and DOCX/PDF export. DOCX import retains the running-story and review subsets described below. General complex multilevel labels, flowing notes and exact source pagination remain unqualified. Import warnings identify that loss. DOCX and PDF preserve ordinary table widths and merged cells; oversized PDF tables scale to the printable width with a notice. Complex merged-cell pagination still needs qualification. PDF reports paragraph/inline font-family substitution rather than pretending that every requested installed font is embedded. Unsupported nodes/marks are reported with retained descendant text where possible. These limits are also returned in each export's `warnings` array.

Native Save updates a bound text file or Alder bundle after checking for external changes. Save As chooses a new destination in the current format; Save a Copy leaves the binding unchanged. Imported DOCX/Markdown/conversion sources start with a suggested working-copy destination because full source-format fidelity is not supported. File-format conversion remains available through Export. The local autosave status describes the workspace copy; the explicit Save result identifies the external file written. Cancelling does not report success. Saved Versions recovers a separate document and leaves the current one open.

File → Print opens the saved-revision PDF proof. Print this PDF opens that exact PDF in the sandboxed desktop viewer, whose print control offers printer, page and copy selection once loaded. It does not print the editing canvas or auto-print a loading page. Closing the window removes its temporary preview file. Windows tests cover proof generation, window opening and cleanup without sending a physical print job; printer drivers and macOS/Linux dialogs still need qualification. PDF body margins now exclude ReportLab's implicit frame padding; unnamed sections no longer insert an empty heading above the first authored block.

Project schema 2 adds stable block identities. Schema 1 projects migrate on validated reads/updates; existing archive container version 1 remains supported. Older builds limited to project schema 1 cannot read newly saved schema 2 projects. Managed updates declare the supported forward migration and block incompatible automatic rollback. Keep original files/backups when exchanging with those builds.

## Validation and collected resources

EPUB generation writes the required first, uncompressed `mimetype` entry. Every build checks the container, package XML, manifest resources, XHTML parsing, spine and navigation. The bundled EPUBCheck then performs full conformance validation. An EPUBCheck error fails the export. The result distinguishes `passed`, `structural-only`, `failed` and checker availability, so a missing checker cannot appear to be full validation. AZW3 runs the bundled Calibre converter as a separate process and reports its actual exit status.

Images are accepted only as collected assets within the project's controlled asset root or as embedded raster bytes. They are decoded and normalised to PNG, stripping active data and EXIF. No export fetches a remote image. HTML preview has a restrictive content security policy. Imports do not execute scripts or fetch external resources. ZIP import validates entry paths, duplicates and the expanded size before processing, with a 100 MB limit. Individual images are limited to 20 MB and 40 megapixels.

The API passes the project's controlled image directory as `options.assetRoot`. Imported assets return `{id,name,mime,data}`; the app writes their bytes to the content-addressed asset store and persists controlled references. Export files receive unique names and are made available only through the controlled export endpoint after a successful build.

## Definition cards

`alder.definition_cards.build_definition_export` renders the author's Voyager design using editable `word`, `ipa`, `partOfSpeech` and `definition` values. Headword and pronunciation share a baseline; a long rule, italic part of speech and wrapped definition follow below on a white square. The supplied definition is preserved exactly: “A Priest of Lucidity and the Manifest Reality.”

PNG, JPEG and vector PDF use one measured layout. Default output is 800 × 800 pixels, with a 256–4096 pixel size range and 72–600 DPI metadata. At the default 96 DPI, the PDF page is 600 × 600 points. Optional separate width/height centre the same square design inside a rectangular canvas. Long headwords shrink together with their pronunciation; long definitions shrink only to a readable minimum, then fail with a clear message if they still cannot fit. No text is silently clipped. Unsupported font glyphs are identified before export. The bundled Liberation Serif font includes the IPA characters in the Voyager example.

## Bundled runtime layout

Packaged builds resolve their resources from `ALDER_RESOURCES_DIR`; development uses `work/bundle-resources` in the project. Required resources are shipped with Alder and do not require the user to install a converter, Java, Python or a font.

- `fonts/LiberationSerif-Regular.ttf`, `LiberationSerif-Bold.ttf`, `LiberationSerif-Italic.ttf`, `LiberationSerif-BoldItalic.ttf`, plus `LICENSE` and `AUTHORS`.
- `tools/epubcheck/epubcheck-5.3.0/epubcheck.jar` and the complete sibling `lib` directory.
- `tools/java/bin/java.exe` or `tools/jre/bin/java.exe`, with the complete portable Java runtime.
- `tools/calibre/ebook-convert.exe` or `tools/calibre/Calibre/ebook-convert.exe`, with the complete portable Calibre distribution.

Developer diagnostic overrides are `ALDER_EPUBCHECK_JAR`, `ALDER_JAVA` and `ALDER_EBOOK_CONVERT`. Discovery prefers packaged resources; installed tools are only a development fallback. Packaging must verify all required resources before producing a release.

Publishing Python dependencies are `python-docx>=1.2`, `reportlab>=4`, `pypdf>=5`, `Pillow>=10`, `beautifulsoup4>=4.12` and `markdown-it-py>=3`. Their dependencies are included in the bundled Python runtime.

## Image properties

Image properties include inline/standalone placement and proportional width (shown in millimetres in the editor), left/centre/right alignment, alternative text and title. These properties survive ordinary DOCX and HTML round trips; PDF applies the image's alignment. Word stores dimensions as integer EMUs, so imported pixel widths can differ by less than one EMU. Oversized images fit the printable area. Inline pictures stay within paragraphs in HTML/EPUB and DOCX, including image-only paragraphs; production PDF embeds them at the baseline and expands ordinary line spacing. Standalone DOCX drawings use a preserved drawing name to retain their placement on reopening. Non-destructive percentage crops retain the original raster. HTML/EPUB carry the visible crop plus original resource metadata; DOCX uses native source-crop properties, qualified through Word 16.0 open/render/resave. PDF uses the cropped pixels. Negative Word crops/padded areas and floating positions report conversion. Anchored wrapping and tagged PDF image descriptions remain unsupported. Image collection does not replace the current editing snapshot; registration and insertion retain typing performed during upload.

## Table appearance and conversion

The Table properties dialog edits table alignment, selected-cell vertical alignment, four padding values, uniform cell borders/shading, minimum row height and column widths. It leaves untouched properties intact. Widths, padding, borders, shading, row minimums and alignment survive DOCX/HTML exchange; PDF applies them. DOCX vertical merges include matching continuation-cell formatting, verified with Word 16.0 rendering and resaving. Different border styles on individual edges are converted to uniform cell borders with a warning. Exact Word row heights become minimum heights so authored content remains visible. Ordinary tables now repeat leading headers in Write/Arrangement and the browser publication prototype. Headers stay with the first body row, and vertical merges move as complete groups when they fit. Oversized groups/rows retain the older line-splitting fallback; repeat-on-split and complex merged/nested pagination remain unqualified.

Table sorting retains leading header rows, uses natural text/numeric ordering, and is disabled for merged tables. Text/table conversion uses tabs and selected paragraphs, preserves inline marks and empty cells, and refuses object-containing tables. Formatting, sorting and conversion each undo in one editor step. Resetting column widths fits the table to its available page width; distributing columns retains the current table width.

## Page geometry

Custom paper dimensions, separate top/bottom/left/right margins and a left binding gutter are stored with the document. Write, Arrangement, HTML, DOCX and PDF share their dimensions and usable-body rules. Headers and footers are separate formatted paragraph stories, edited through the formatting/context menu, Settings → Publication, or a double-click in a page margin. First-page and odd/even variants, per-section links, edge distances and native page/total-page fields are retained. Explicit blank stories differ from linked stories. Running text is outside body counts, proofreading and narration; changes have project undo and Cancel leaves the document untouched.

Write, Arrangement and desktop PDF share running-story paint, including measured tabs/leaders and exact leading. Text that exceeds the available margin is rejected on Apply or publication rather than silently clipped. Native Word 16.0 update/render/resave qualification covers formatted paragraphs, first/odd/even stories, independent section links, PAGE and NUMPAGES. HTML/EPUB preserve running metadata for Alder; reflowable readers do not repeat it on arbitrary screens. TXT/Markdown report its omission. Direct backend PDF renders the paragraph subset and live page numbers but retains cached total-page values. General tables/images in running stories, automatically enlarged margins, chapter/heading fields and full-book editing-page numbering across separately opened chapters remain open. Complex imported Word running stories convert to plain paragraphs with an explicit warning.

Display zoom no longer changes table pagination: pages are laid out at natural scale and transformed for viewing, with application zoom compensated. The Windows fixture preserves its seven-page map at UI scales 50/100/150% and Write zooms 50/100/300%. This does not establish identical typesetting across platforms or replace ReportLab with the browser publication prototype.

Opening a DOCX uses its first section's paper, margins, gutter, starting page number and supported number format. Next-page, odd-page and even-page sections retain their own paper, orientation, four margins and binding gutter. Write's formatting/context menu provides Insert section break and Section properties, including removal of a break with undo. Page Layout and Section properties support decimal, lower/upper Roman and lower/upper alphabetic page numbering, with section restarts or continuation. Alphabetic page labels follow Word's A–Z, AA, BB convention. Continuing numbering inserts blank parity sheets where required; explicit restarts advance the label to the requested parity without an extra sheet. Blank parity pages have no running header/footer. DOCX exports/imports genuine sections and numbering, PDF switches physical page templates, and HTML retains section metadata and named page styles. EPUB/Markdown report fixed section layout conversion. Column sections, chapter-prefixed or other unsupported numbering, and mirrored/top binding remain conversions with notices. Importing into an existing document retains the destination's first-page settings.

The Templates library saves reusable document content and formatting, or formatting alone. New shows matching templates alongside the ordinary blank-document choice. Each use creates an independent document, reidentifies its structural/style/asset relationships, verifies and copies collected images, and preserves section/numbering settings. Source documents, Sandbox drafts, external file bindings and version histories remain independent. Removing a library template is reversible; documents already created from it remain available. Templates and their collected resources are local application data and are included in a full Alder data-directory backup.

Numbering qualification uses `scripts/page-numbering-fixture.py` with the existing isolated Word harness. Five Word 16.0 round trips check odd/even restart adjustment, continuation, repeated-letter labels and large Roman values against the backend PDF labels. The desktop checks additionally verify numbering after earlier text gains pages and incremental/full layout agreement. The declared scope is logical page labels and retained source semantics; Word and the production PDF still use different body-layout engines.

Arrangement shows each page's actual size. Sentences and paragraphs can cross sections; whole pages can move within their section using dragging, the context menu or Alt+Up/Down, retaining section geometry and separate undo. Moving entire pages between sections is not yet supported. Rich section-specific running stories, columns and mirrored margins remain open. Old uniform margins remain supported; impossible legacy pairs are reduced proportionally with a report, while new impossible combinations are rejected.

Section qualification includes a four-page portrait/landscape/A5 browser fixture, scale-independent boundaries, later-page caret placement, repeated table headers, snapshot geometry and actual workspace save/reopen/Arrangement operations. Native Word 16.0 renders and resaves the structured fixture with mixed page sizes and odd section starts, including an even starting page number. Desktop PDF uses the captured editing page map described above. Direct backend ReportLab PDF uses the same physical dimensions but independently typesets body content.

Continuous sections retain body flow on the current sheet when its paper dimensions match. Horizontal margins apply immediately; vertical margins, running stories and numbering apply on the following sheet. Changing paper dimensions starts a new sheet. A mid-page numbering restart counts the shared sheet but keeps that sheet's existing printed label, matching Word. Six original fixtures qualify these transitions against Word 16.0, including first-page stories and independent margins. Windows Write, Arrangement and desktop PDF agree on page ownership and paper dimensions. Incremental edits preserve pending section settings and match fresh layout. HTML/EPUB preserve the metadata; direct backend PDF reports its next-page conversion. Columns remain unimplemented.

## Search and recovery

Find → Advanced provides local regular-expression search, captured-text replacements and a preview. Empty-position matches are not accepted for replacement. The search worker is terminated after 1.5 seconds rather than blocking editing, and results are invalidated when the source changes. Whole-book replacements use durable project undo; this remains separate from local editor undo.

Failure-injection tests cover failed external-file flushes, failed file-binding writes, concurrent bindings, a private SQLite database growth limit, and process exit during an uncommitted save. The last committed document/history and prior binding remain available. These checks do not certify every filesystem or power-loss scenario.

## Review comments

Anchored plain-text comment threads retain authors, timestamps, replies and resolved status in Alder, HTML/EPUB metadata and native Word comments. Word 16.0 open/render/resave is qualified for a multi-paragraph range with replies and resolution. Rich imported comments retain plain wording and report unsupported embedded objects/fields; unsupported body anchors remain available as incomplete annotations. Partial selection moves and rich review content still need broader qualification.

The Export window can omit review comments from an exported copy without deleting them from the project. It reports pending changes and offers retained revisions, final wording or original wording. Plain text, Markdown and PDF omit comments and default to final wording, reporting conversion. This does not accept source revisions or remove document-author metadata.

Tracked inline insertions/deletions, ordinary paragraph boundaries and character/paragraph formatting retain authors/timestamps in Alder and HTML/EPUB. Native DOCX uses insertion/deletion wrappers, paragraph-mark revisions and previous run/paragraph properties. A production fixture survives Word 16.0 open/render/resave/reimport with original/final wording intact, including nested insertion/deletion by different authors, a run-format change and paragraph alignment. Unsupported structural moves, field/object revisions, named-style/link/code revisions and overlapping separate formatting histories are explicitly refused where Word conversion cannot retain review decisions. Paragraph font/style revisions requiring companion run changes and deleted boundaries between differently formatted paragraphs also require review before Word exchange. Alder retains both original appearances. Full tracked-change compatibility and cross-platform qualification remain unfinished.
