# Alder publishing and definition cards

Desktop PDF carries document/title language, heading outlines and semantic tags for headings, links, images, lists, tables and notes. Repeated table headers belong to their continuation rows; decorative/running paint stays outside reading order. Windows qualification includes nine-page ordinary and six-page column exports with exact marked-content ordering, row/column scopes, image descriptions, inline-image ownership and footnote placement (`test-tagged-pdf-desktop.mjs`, `check-tagged-pdf.mjs`). Direct backend PDF is not tagged. Chromium's [tagged PDF API](https://www.electronjs.org/docs/latest/api/web-contents#contentsprinttopdfoptions) is experimental; PDF/UA and PDF/A are not claimed. Complex merged/nested tables, broader multilingual cases and native screen readers on all supported platforms still need qualification.

More formatting → Check accessibility reviews included document content or the current Sandbox draft for structural heading, image, table and link issues. Go to item opens the existing editor/properties; checks never rewrite wording. Notes and active running variants are included. This does not automatically assess description quality or certify conformance. The interaction fixture is `test-accessibility-desktop.mjs`.

Running headers and footers support formatted paragraphs, tables and inline/block images. They reuse the table and image property controls, preserve merged cells/crops/alt text, and remain separate from body narration and counts. Windows editing, undo, save/reopen, Arrangement and shared desktop PDF checks pass at 50/100/150% UI scales. Native Word 16.0 renders and resaves the supported tables/images; DOCX, HTML and EPUB preserve these stories. HTML/EPUB embed their original raster bytes in running metadata. Header/footer content must fit its page margins; general floating objects and automatic margin enlargement remain open.

The publication service builds every output from the same explicit collation. It resolves section order, placement order, inclusion, a placement's selected variant or its clip's accepted variant, and frozen document/text snapshots. A muted audition track remains in the written publication unless its placement is excluded. Draft clips with no included placements are reported and omitted. Repeated placements are reported and repeated. Missing references fail visibly instead of silently changing the manuscript.

## Supported document formats

Paragraph footnotes can continue across different page dimensions in Write, Arrangement and desktop PDF. The unread text reflows at the destination width while retaining narration offsets. Lists/tables/pictures in changing-width continuations remain unsupported and fail explicitly. Native Word 16.0 clips the qualified changing-size continuation fixture even in current compatibility layout, so desktop DOCX refuses an individual note crossing different dimensions; documents with mixed sections whose notes stay within one geometry remain exportable. Direct backend DOCX requests desktop measurement for potentially affected documents. See `test-note-widths-desktop.mjs` and `check-note-widths.py`.

Index entries → Page range uses an existing bookmarked passage. Stable identities survive renaming and rich copies; measured page labels update with the document. HTML/EPUB preserve the relationship, and DOCX uses the native [Word XE range switch](https://support.microsoft.com/en-us/word/field-codes-xe-index-entry-field). Missing/incomplete ranges are flagged and refuse Word export. The Windows desktop and Word 16.0 render/resave fixture confirms the same range after adding a page, plus persistence, undo, Arrangement and UI scaling (`test-index-desktop.mjs`, `check-index-ranges.py`). Custom sort keys, multiple index types and international collation remain outside this subset.

More formatting → Insert equation provides local visual/LaTeX editing, Inline/Own paragraph placement and a reading description. Presentation MathML is retained by Alder, HTML and EPUB; DOCX uses editable Office Math for supported fractions, roots, scripts, accents, matrices, delimiters and large operators. Native Word 16.0 render/resave retains the tested formulas, with Word's own font/spacing conventions. Custom descriptions survive Alder/HTML/EPUB; Word imports regenerate them. Desktop PDF retains vector formulas and tagged reading alternatives; oversized formulas fail desktop PDF/DOCX publication rather than clipping. TXT/Markdown use descriptions with a notice. Equation exports to ODT/RTF/AZW3 and direct backend PDF fail explicitly. Unsupported MathML/Office Math structures and external resources are refused. MathLive/KaTeX and the STIX Two Math font are bundled for offline use with their licences. Windows tests cover editing/undo, clipboard, persistence, UI scaling, Arrangement, highlight geometry and actual Word/PDF outputs. Note/running/form stories, wider Office Math fidelity, native screen readers and Mac/Linux qualification remain open. Fixtures: `test_equations.py`, `equations.test.ts`, `test-equations-desktop.mjs`, `check-equations.py`.

New → Word document → Template offers DL/C5 envelopes and 21 labels on A4 (63.5 × 38.1 mm, 2.5 mm horizontal gaps). Address fields remain editable through properties; empty prompts do not print. Saved stock checks verify geometry and measured content before desktop PDF/DOCX, refusing overflow rather than clipping or shifting labels. Settings → Page Layout → Check stationery fit can be disabled for ordinary-page use. Print at actual size (100%), one-sided, with matching paper and the correct feed tray in the native printer window. These are digital templates, not certified printer calibration. Windows/Word 16.0 render/resave checks retain all addresses once on one page, with tested address origins within 0.75 mm of Alder. Native Word uses current table layout for stock; imported DOCX/HTML and clipboard tables retain fractional grid widths. Stock checking persists in Alder/templates, while exported Word files retain ordinary tables/content controls and need their fit rechecked after external edits. Other paper stocks, printer-driver presets and hardware/Mac/Linux printing qualification remain open. Fixtures: `test_stationery.py`, `test-stationery-desktop.mjs`, `check-stationery.py`. Dimensions correspond to [Avery's 63.5 × 38.1 mm grid](https://www.avery.co.uk/template-l7160) and the [DL/C5 envelope dimensions](https://www.royalmailtechnical.com/rmt_docs/User_Guides_2024/Guide_For_Clear_Addressing_20240402.pdf); printer-specific alignment has not been certified.

More formatting → Insert form field adds plain/rich text, checkbox, ISO date and rich block controls. Selected properties (double-click or Enter) edit values, names/tags and content/deletion restrictions. Tab traverses selected controls; Space toggles an unlocked checkbox. Rich blocks retain paragraphs, lists, tables and collected pictures. Empty prompts are excluded from speech, Arrangement and output. Restrictions are reversible editing aids, not encryption. Native DOCX text/rich/date/checkbox controls and their locks survive Word 16.0 render/resave; HTML/EPUB preserve Alder control metadata. Unsupported date displays convert to ISO with notices, or retain their wording as a plain field when no valid date is available. Nested controls, XML data bindings, repeating groups and unsupported review combinations are not supported; conversion reports or explicit refusal protect authored content. RTF/ODT/plain formats retain values and report loss of interactive behaviour. Windows fixtures cover keyboard editing, locks, clipboard, undo, persistence, scaling, Arrangement and PDF; native Mac/Linux qualification remains open. See `test_form_fields.py`, `formFields.test.ts`, `form-fields-fixture.py` and the two form desktop tests. The native format follows Microsoft's [content control definitions](https://learn.microsoft.com/en-us/office/client-developer/word/content-controls-in-word).

More formatting → Mail merge uses local UTF-8 CSV with comma/semicolon/tab separators. Insert named fields, map columns, preview records and create up to 100 selected copies per operation. Values remain literal text, including empty/multiline values, Unicode and leading zeroes. Copies preserve formatting, tables, notes, running stories and collected pictures; they have independent identities, histories and file bindings. The source and CSV stay unchanged. A stale template, missing mapping, pending review or failed batch does not publish partial documents. Save, Export and Print use the existing document controls. DOCX retains native MERGEFIELD instructions, verified through Word 16.0 render/resave; HTML/EPUB retain semantic fields. Imported [Word data connections](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.wordprocessing.mailmerge) are not executed. Conditional merge rules, database sources, automatic email delivery and cross-platform native qualification are outside this workflow. Fixtures: `test_mail_merge.py`, `mailMerge.test.ts`, `mail-merge-fixture.py`, `test-mail-merge-desktop.mjs`.

RTF uses a bounded local reader/writer for editable Unicode paragraphs/headings, character formatting, spacing/indents/leading/tabs, safe links/bookmarks, embedded PNG/JPEG pictures, native notes, default running stories and document geometry. First Save proposes a separate copy; later saves retain the chosen RTF binding. Native Word 16.0 render/resave and Windows editing/undo, save/reopen, UI scaling, Arrangement and PDF checks use `rtf-fixture.py`, `test-rtf-desktop.mjs` and `test_rtf.py`. Ordinary tables and list labels convert to text with notices; advanced sections/styles/furniture, arbitrary fields, positioned objects and automatic list/table structure are outside this subset. Imported review changes/comments and unsupported embedded objects fail explicitly. External instructions never execute. Preserve Alder/DOCX for these richer features. Cross-platform and LibreOffice exchange remain unqualified. DOCX also imports embedded legacy VML raster pictures, including width, crop and descriptions, as used by Word's RTF conversion; unsupported geometry/effects report conversion. The image properties follow Microsoft's [VML image data definitions](https://learn.microsoft.com/en-us/windows/win32/vml/msdn-online-vml-imagedata-element).

ODT uses native OpenDocument structures for editable paragraphs/headings, character formatting, paragraph spacing/indents/tabs/shading/borders, ordinary nested lists, merged tables with repeated headings, embedded raster pictures, notes, default running stories and document-wide page geometry. It appears in the existing export picker; imported ODT saves first to a proposed separate copy and retains its format on later saves. The ODF 1.3 package, document and manifest schemas and Word 16.0 render/resave are checked by `odt-fixture.py`; `test-odt-desktop.mjs` covers editing/undo, saved bindings, UI scaling, Arrangement and PDF. Source styles become direct formatting. Advanced sections, first/even headers, custom numbering, furniture, anchored objects and generated fields report conversion. Imported unresolved revisions/comments and unknown embedded objects fail explicitly; use DOCX to retain editable review. External images are never fetched and macros never run. Exact layout across applications and LibreOffice/Mac/Linux exchange are not yet qualified. The format follows the [ODF 1.3 package specification](https://docs.oasis-open.org/office/OpenDocument/v1.3/OpenDocument-v1.3-part2-packages.html) and [document schema](https://docs.oasis-open.org/office/OpenDocument/v1.3/OpenDocument-v1.3-part3-schema.html).

Page Layout and Section properties offer uniform page borders, centred text watermarks and physical line numbering. Single/double/dashed/dotted borders support width, colour, page-edge distance and first/all/except-first pages. Watermarks support text, font, colour, dimensions and rotation. Line numbers support start, interval, distance and continuous/page/section restarts; paragraphs/styles can suppress them. These are derived paint in Write, Arrangement and desktop PDF, separate from authored wording, counts and speech. Native Word 16.0 render/resave fixtures qualify the corresponding page borders, VML text watermarks and native line-number settings. HTML/EPUB preserve settings but do not promise repeating furniture in arbitrary reflowable readers. Plain formats warn about omission; headless PDF requires desktop export for watermarks/line numbers. Unequal/art/text-relative borders, picture/variant-specific watermarks and general floating-object/bidirectional line numbering remain outside the qualified subset. Fixtures: `page-border-fixture.py`, `watermark-fixture.py`, `line-numbering-fixture.py`, their desktop tests and `test-line-number-layout-desktop.mjs`.

Generated indexes use point entries with up to three term levels, optional See/See also text and measured page references. The existing contents dialog selects an index and its entry style. DOCX uses native XE/INDEX fields, qualified through Word 16.0 update/render/resave; supported whole-paragraph native INDEX fields also import without Alder wrappers. HTML/EPUB retain structured entries; Markdown reports conversion. Page ranges, custom sort keys, multiple named indexes, general Word switches and international collation remain unqualified.

Equal-width section columns, gaps, separator lines and explicit column breaks share Write/Arrangement/desktop PDF geometry. Continuous section tails balance and reuse the remaining sheet. Windows checks cover mixed column counts, native typing, scales/zoom, tables and parallel top-aligned split cells. Word 16.0 renders and resaves ordinary and balanced continuous columns; HTML/EPUB retain settings. Unequal Word widths report conversion. Direct backend PDF uses independent column frames and converts continuous transitions to page starts. General merged/nested table qualification remains open.

Footnotes support per-page restarts derived from settled physical anchor pages; native Word and three-page/five-page desktop fixtures verify numbering, cross-references and continuations (`page-notes-fixture.py`, `test-page-notes-desktop.mjs`, `check-page-notes.py`). Reflowable/plain exports report continuous numbering. Footnotes and endnotes retain paragraph bodies, character formatting, links, inline/standalone raster images and automatic numbering. Notes reuse image properties and collection, including crop/size/alignment/descriptions/decorative status; native Word note parts and HTML/EPUB preserve image bytes and metadata. The Windows three-page image-note fixture checks continuations, narration offsets, local/project undo, upload, save/reopen, Arrangement and tagged image ownership (`note-images-fixture.py`, `test-note-images-desktop.mjs`, `check-note-images.mjs`). Desktop footnotes reserve space with their anchors and continue across pages; endnotes follow the body. Number format/start, section restart and bottom-of-page/below-text placement survive native Word 16.0 open/update/render/resave, including NOTEREF number and PAGEREF page references. HTML/EPUB retain semantic note metadata; TXT/Markdown convert to numbered references and a note list with a warning. Direct backend PDF rejects notes and requires desktop PDF. Section properties can inherit or override note formats, starts, restart rules and footnote placement. Continuous numbering counts earlier references across restarted sections, matching Word. Endnotes use available space after the final body text and continue when necessary; section controls/undo and a six-page Word/desktop fixture are covered by `section-notes-fixture.py` and `test-section-notes-desktop.mjs`. Note bodies also support nested lists, outline/continued numbering and editable tables with merged cells, row splitting, cell formatting and repeated headings. The six-page Windows/Word rich-note fixture verifies all 107 unique content markers, local/project undo, save/reopen and list/table structure (`rich-notes-fixture.py`, `test-rich-notes-desktop.mjs`). Oversized kept rows now split at measured text/image boundaries, carrying repeated headings and retaining the authored row setting. Desktop DOCX includes note-row measurements and uses the current [Word compatibility mode](https://learn.microsoft.com/en-us/office/vba/api/word.wdcompatibilitymode) for note tables; the old mode clipped a long endnote row in native testing. The five-page desktop/six-page Word fixture retains all 142 markers and both short-row keep flags after Word resave (`kept-notes-fixture.py`, `test-kept-note-rows-desktop.mjs`). A single ink object taller than its printable area still requires resizing. End-of-section placement, mixed-width continuation, complex column/table combinations, rich-note PDF table/list tags and cross-platform qualification remain unqualified. Ordinary/column PDF note reading order is covered by the tagged-output fixtures above. Imported unsupported numbering settings report conversion; custom Word reference marks are rejected with the original file preserved.

List properties supports nine-level outline templates with compound patterns, starts, restart rules, indentation and separated continuations. Labels stay derived and do not become authored prefixes. Supported native Word outline import requires nine complete levels, left-aligned markers and space suffixes. Native Word 16.0 update/render/resave checks cover mixed formats, never-restart descendants and bulleted roots. Ordinary and outline alphabetical/Roman labels follow Word's Z/AA/BB and extended Roman conventions in Write, desktop/backend PDF and HTML. HTML/EPUB retain outline templates; Markdown reports their conversion.

Optional paragraph/style hyphenation uses bundled local dictionaries in Write, running stories, Arrangement and desktop PDF; it is off by default and does not change authored words. Language tags and explicit on/off overrides survive DOCX/HTML/EPUB exchange. Native Word 16.0 render/resave checks retain those settings. Browser publication waits for dictionary results and layout, retains visible page-boundary hyphens and excludes unused break characters from PDF extraction. Ordinary reflowable HTML readers use their own CSS hyphenation support; direct backend PDF uses its own dictionary-backed line layout. Missing local dictionaries fail explicitly. Full script/IME/accessibility qualification and large-document performance targets remain open.

Running headers and footers support automatic Heading 1–6 fields, using the first matching heading on the physical sheet or the nearest preceding heading (then the first following heading). Values track editing and Arrangement and are calculated in desktop PDF; direct backend PDF uses its own page layout. Body heading fields resolve on insertion/Update fields and export. Native Word STYLEREF update/render/resave is qualified for built-in and dedicated custom heading styles. Mixed styles at the same level or a style shared with ordinary text cannot be represented by one native STYLEREF: DOCX export asks for one dedicated style rather than writing an incorrect field. External instructions with incompatible style scope or unsupported switches retain cached wording with a conversion warning. `test-running-headings-desktop.mjs` and `running-headings-fixture.py` cover these behaviours. General floating running objects and full-book page numbering in chapter-local editing remain open.

Table properties includes per-row keep-together or allow-across-pages settings. DOCX retains native row break flags, including after Word 16.0 rendering/resaving; HTML/EPUB preserve them. Write divides paragraph cells and vertical merges into independent cell page ranges, repeated headers and no orphaned header. Middle/bottom alignment applies to each physical fragment and honours unsplit minimum heights. Top-aligned container cells support nested tables, lists and quotations; nested/sibling headings retain separate widths and offsets. Windows fixtures cover native editing/undo, save/reopen, Arrangement, UI scale/zoom and all markers once in 1–5-page desktop PDFs. Native Word checks cover merge spans, nested structure and the qualified alignment offsets. DOCX row minima account for Word's extra padding/border space. Word uses each row's largest top/bottom margins; unequal vertical padding reports conversion and imports with that rendered geometry. Arrangement and desktop PDF freeze measured cell positions and borders without print-time reflow. Block/floating objects, aligned nested containers, complex columns/notes and merged/nested semantic reading order still need qualification. Direct backend PDF honours row choices through ReportLab but uses its separate pagination. See `test-merged-tables-desktop.mjs`, `test-nested-tables-desktop.mjs` and their native Word fixtures.

Heading numbering supports six decimal levels, inherited styles, explicit removal and level restarts. Heading text/number/page cross-references retain native Word fields and stable targets. In-document contents collect chosen heading levels from included chapters, with optional page numbers and an entry style. Desktop insertion, field updating and PDF calculate these numbers from the complete publication, including section numbering/restarts; HTML/EPUB preserve cached page values. Native Word 16.0 updates and resaves the supported TOC/PAGEREF representation and entry typography. Multiple contents fields share Word's global TOC styles, which is reported when their Alder entry styles differ. General external Word TOC instructions and non-desktop page-reference recalculation remain unqualified.

## Validation and collected resources

EPUB generation writes the required first, uncompressed `mimetype` entry. Every build checks the container, package XML, manifest resources, XHTML parsing, spine and navigation. The bundled EPUBCheck then performs full conformance validation. An EPUBCheck error fails the export. The result distinguishes `passed`, `structural-only`, `failed` and checker availability, so a missing checker cannot appear to be full validation. AZW3 runs the bundled Calibre converter as a separate process and reports its actual exit status.

Images are accepted only as collected assets within the project's controlled asset root or as embedded raster bytes. They are decoded and normalised to PNG, stripping active data and EXIF. No export fetches a remote image. HTML preview has a restrictive content security policy. Imports do not execute scripts or fetch external resources. ZIP import validates entry paths, duplicates and the expanded size before processing, with a 100 MB limit. Individual images are limited to 20 MB and 40 megapixels.

The API passes the project's controlled image directory as `options.assetRoot`. Imported assets return `{id,name,mime,data}`; the app writes their bytes to the content-addressed asset store and persists controlled references. Export files receive unique names and are made available only through the controlled export endpoint after a successful build.

## Definition cards

`alder.definition_cards.build_definition_export` renders the author's Voyager design using editable `word`, `ipa`, `partOfSpeech` and `definition` values. Headword and pronunciation share a baseline; a long rule, italic part of speech and wrapped definition follow below on a white square. The supplied definition is preserved exactly: “A Priest of Lucidity and the Manifest Reality.”

PNG, JPEG and vector PDF use one measured layout. Default output is 800 × 800 pixels, with a 256–4096 pixel size range and 72–600 DPI metadata. At the default 96 DPI, the PDF page is 600 × 600 points. Optional separate width/height centre the same square design inside a rectangular canvas. Long headwords shrink together with their pronunciation; long definitions shrink only to a readable minimum, then fail with a clear message if they still cannot fit. No text is silently clipped. Unsupported font glyphs are identified before export. The bundled Liberation Serif font includes the IPA characters in the Voyager example.

## Bundled runtime layout

Packaged builds resolve their resources from `ALDER_RESOURCES_DIR`; development uses `work/bundle-resources` in the project. Required resources are shipped with Alder and do not require the user to install a converter, Java, Python or a font.

- `fonts/LiberationSerif-Regular.ttf`, `LiberationSerif-Bold.ttf`, `LiberationSerif-Italic.ttf`, `LiberationSerif-BoldItalic.ttf`, plus `LICENSE` and `AUTHORS`.
- `tools/epubcheck/epubcheck-5.3.0/epubcheck.jar` and the complete sibling `lib` directory.
- `tools/java/bin/java.exe` or `tools/jre/bin/java.exe`, with the complete portable Java runtime.
- `tools/calibre/ebook-convert.exe` or `tools/calibre/Calibre/ebook-convert.exe`, with the complete portable Calibre distribution.

Developer diagnostic overrides are `ALDER_EPUBCHECK_JAR`, `ALDER_JAVA` and `ALDER_EBOOK_CONVERT`. Discovery prefers packaged resources; installed tools are only a development fallback. Packaging must verify all required resources before producing a release.

Publishing Python dependencies are `python-docx>=1.2`, `reportlab>=4`, `pypdf>=5`, `Pillow>=10`, `beautifulsoup4>=4.12` and `markdown-it-py>=3`. Their dependencies are included in the bundled Python runtime.

## Image properties

Image properties include inline/standalone placement and proportional width (shown in millimetres in the editor), left/centre/right alignment, alternative text and title. These properties survive ordinary DOCX and HTML round trips; PDF applies the image's alignment. Word stores dimensions as integer EMUs, so imported pixel widths can differ by less than one EMU. Oversized images fit the printable area. Inline pictures stay within paragraphs in HTML/EPUB and DOCX, including image-only paragraphs; production PDF embeds them at the baseline and expands ordinary line spacing. Standalone DOCX drawings use a preserved drawing name to retain their placement on reopening. Non-destructive percentage crops retain the original raster. HTML/EPUB carry the visible crop plus original resource metadata; DOCX uses native source-crop properties, qualified through Word 16.0 open/render/resave. PDF uses the cropped pixels. Left/right paragraph-anchored square wrapping and text spacing are available in Image properties and survive DOCX/HTML/EPUB exchange. Native Word 16.0 rendering/resaving, page-edge flow, columns, cells, Arrangement and desktop PDF are qualified by the wrapped-picture fixtures. Other floating positions and negative Word crops/padded areas report conversion. Note/running-story pictures remain inline or standalone. Desktop PDF image descriptions are qualified in the tagged-output fixtures above. Image collection does not replace the current editing snapshot; registration and insertion retain typing performed during upload.

## Table appearance and conversion

The Table properties dialog edits table alignment, selected-cell vertical alignment, four padding values, uniform cell borders/shading, minimum row height and column widths. It leaves untouched properties intact. Widths, padding, borders, shading, row minimums and alignment survive DOCX/HTML exchange; PDF applies them. DOCX vertical merges include matching continuation-cell formatting, verified with Word 16.0 rendering and resaving. Different border styles on individual edges are converted to uniform cell borders with a warning. Exact Word row heights become minimum heights so authored content remains visible. Ordinary tables now repeat leading headers in Write/Arrangement and the browser publication prototype. Headers stay with the first body row, and vertical merges move as complete groups when they fit. Oversized paragraph/image rows and vertical-merge groups flow independently, including top-aligned nested tables/lists and repeated nested headings. Middle/bottom alignment includes qualified paragraph/image cells. Desktop DOCX export measures kept rows and permits splitting for oversized rows in the copy, with a notice; this prevents Word clipping their continuation. Source row settings are unchanged, and stale layout measurements cannot export a newer revision. Direct backend export without measurements reports this limitation. Aligned nested containers and complex table/column/note combinations remain unqualified.

## Search and recovery

Find → Advanced provides local regular-expression search, captured-text replacements and a preview. Empty-position matches are not accepted for replacement. The search worker is terminated after 1.5 seconds rather than blocking editing, and results are invalidated when the source changes. Whole-book replacements use durable project undo; this remains separate from local editor undo.

Failure-injection tests cover failed external-file flushes, failed file-binding writes, concurrent bindings, a private SQLite database growth limit, and process exit during an uncommitted save. The last committed document/history and prior binding remain available. These checks do not certify every filesystem or power-loss scenario.
